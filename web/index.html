How a check runs

  1. 1

    Reads the chain

    Your browser fetches the template substate from the public Ootle indexer and decodes the WASM inside it.

  2. 2

    Hashes it in your browser

    The bytes are hashed with sha256 right here, with crypto.subtle. No server tells you what the hash is.

  3. 3

    Finds the rebuild

    A public GitHub Actions run built the claimed commit offline, with the network cut, a pinned toolchain and recorded settings.

  4. 4

    Compares byte for byte

    The two sha256 hashes are held side by side. Anything short of 32 equal bytes out of 32 is not a match.

  5. 5

    Reads the attestation

    It reads OneScan's SourceRegistry on mainnet and counts an entry only if the trusted key signed it and its hash equals the live bytes.

What a proof does not tell you

  • Verified source is not an audit. A match says which public commit built the bytes. It does not say the code is safe.
  • The method flags are hints from argument types and names. The ABI does not say who may call each method.
  • The register covers November contest templates with public source. Templates without source cannot match anything.
  • An attestation is a statement by OneScan's key. The real proof is that anyone can repeat the rebuild.
