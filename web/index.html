How it works

From opaque bytes to a public, checkable fact.

No trust in this website is required: every step can be re-run from the public workflow.

  1. 01

    Fetch what the chain holds

    The template substate is read from the Ootle mainnet indexer and its WASM binary decoded from CBOR.

  2. 02

    Rebuild in isolation

    The claimed repo at the claimed commit is compiled in a GitHub Actions job with the network cut, then passed through the same wasm-opt step the wallet applies.

  3. 03

    Compare sha256

    On-chain bytes and rebuilt bytes are hashed. Equal hashes mean that commit builds exactly what is deployed; nothing is approximated.

  4. 04

    Attest on chain

    Matches are written to OneScan's SourceRegistry component on Ootle mainnet, signed by the verifier key, readable by any wallet or explorer.

Why it matters

Every call to a template signs against code you cannot read.

A wallet shows a function name and its arguments. The logic behind them is compiled bytes. A GitHub link in a README proves nothing on its own; it only counts if that exact commit rebuilds the exact bytes on chain. OneScan turns that check into something anyone can repeat.

Verified source is not an audit. A match proves which public commit built the bytes. It does not mean the code is safe. Read the source.
